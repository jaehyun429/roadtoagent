2. browser_fallback description
모델이 이 도구를 언제 고르면 안 되는지를 적는 게 핵심입니다. 세 경우를 생각해보세요:

다른 도구로 될 수 있는 일 → 쓰면 안 됨
다른 도구가 COURSE_NOT_FOUND를 줬다 → 과목이 없는 거지 도구가 못 하는 게 아님 → 쓰면 안 됨
다른 도구가 아예 없는 종류의 일(출석, 계획서) → 이때만
그리고 비용을 한 줄 적으세요. "느리고 토큰이 많이 든다"가 들어가면 모델이 마지막 수단으로 취급합니다. 마라톤 서버 description 리뷰 때 "뭘 돌려주는지"를 적으라고 한 것처럼, 여기선 "언제 쓰지 말지"를 적는 겁니다.
